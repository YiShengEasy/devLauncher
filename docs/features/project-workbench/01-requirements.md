# 需求说明

## 背景与问题

DevLauncher 已具备项目任务发现、配置文件编辑、终端和工作流，但它们尚未形成稳定的项目上下文：

- 已扫描项目只是本地历史条目，缺少稳定 ID、可理解的状态和显式信任边界。
- 项目任务当前只发现 Runme 命名 Markdown 代码块；`package.json`、Makefile、Taskfile 与 CI 中已声明的任务无法安全地统一呈现。
- 将项目任务保存为工作流时保存的是当前 Shell 命令快照；项目移动、任务改名或文档更新后，不容易判断该快照是否仍对应原任务。
- 工作流运行状态驻留在进程内存，应用重启后没有统一的运行记录，也不能跨“项目任务”和“工作流”查看最近结果。

用户需要的是本地开发项目的一处可信工作台，而不是另一个云端部署控制台。

## 用户与场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 独立开发者 | 在多个本地仓库之间切换，启动、测试并查看配置 | 选择一次项目，在同一窗口找到可信任务、配置和最近运行。 |
| 测试/运维人员 | 复核测试、迁移或发布任务 | 先看到任务来源、命令预览和风险，再明确决定是否启动。 |
| 使用 Codex 的开发者 | 让助手整理项目任务或创建工作流 | 助手只能读取、发现和预览；高影响执行仍在桌面端确认。 |
| 项目迁移者 | 仓库换了本地位置 | 更新项目本地根目录后，已有引用可以重新解析或明确显示为失效。 |

## 产品原则

1. **本地优先**：项目根目录、任务命令、配置内容和运行记录不上传、不默认同步。
2. **发现不等于信任或执行**：扫描永远只读；可执行任务需要清晰来源、风险和用户确认。
3. **一个项目上下文，多种入口**：项目任务窗口、工作流、终端、搜索和电子宠物复用同一项目/运行模型，而不是各自持有副本。
4. **引用优于脆弱快照**：新建项目任务工作流保存可重新解析的任务引用；为复现保留当次运行的不可变、安全脱敏快照。
5. **渐进兼容**：现有 Runme 任务、Shell 快照工作流和本地历史继续可用，不自动执行迁移或改变既有键位。

## 功能需求

### FR-001 项目档案

- 用户可从“项目任务”选择的本机目录创建或更新项目档案。
- 每个档案具有稳定 `projectId`、显示名、创建/最近访问时间和本机根目录；根目录必须在保存时 canonicalize 为存在的目录。
- 本机根目录是设备本地信息。同步配置如需展示项目引用，只能保存不含绝对路径的 `projectId`、显示名和可选仓库标识；不应将本机路径写入现有云同步快照。
- 项目根目录不可用、移动或不再匹配仓库标识时，状态为“需要重新定位”，禁止基于旧路径直接执行。
- 迁移现有 `projecttasks_data.json` 的项目历史、任务收藏和配置收藏；迁移后保留原历史顺序和最多 24 项的上限。

### FR-010 项目概览

- 项目工作台显示项目概览、任务、配置、工作流和运行五个上下文区域；首版允许保留现有独立窗口，但数据与状态必须共用。
- 概览至少显示：项目名、当前本机根目录、Git 仓库/分支（可用时）、任务来源摘要、配置文件数、关联工作流数和最近一次运行。
- 读取 Git 信息只能调用只读命令并设定超时；没有 Git、命令不可用或超时必须降级为“未检测到”，不得阻断窗口。
- 搜索结果和虚拟键盘打开的项目工具必须带入同一个已验证项目上下文，不能靠全局可变的最后目录猜测目标。

### FR-020 任务发现适配器

- 引入统一的只读 `ProjectTaskProvider` 抽象，输出来源、稳定来源键、展示名、命令预览、工作目录、风险、可执行性和诊断信息。
- 首个适配器继续复用 Runme；其显式命名任务规则、后端路径校验和 Runme 不可用时的只读降级保持不变。
- 后续适配器按优先级支持：`package.json` scripts、Makefile、Taskfile 与 CI 中显式声明的手工任务。它们只枚举声明的任务，绝不运行 package manager、Make、容器或 CI。
- 同名候选项必须按来源分组，不自动猜测哪一个更安全；用户可过滤来源并查看原始定义文件和行号（可获取时）。
- 扫描有数量、文件大小、深度和单个子进程超时上限；超限产生可理解警告而非静默遗漏。

### FR-030 任务、工作流与配置关联

- 用户可将已确认的候选任务保存为工作流步骤。新步骤保存 `ProjectTaskRef`（`projectId`、provider、sourceKey、相对定义文件、任务名）而非仅保存拼接后的 Shell 字符串。
- 每次运行前，后端使用当前项目根目录重新发现/验证引用，再生成经过 Shell quoting 的命令；解析失败时显示“任务已变化或项目未定位”，不执行旧命令。
- 为兼容已有工作流，现有 `ScriptAction` 不自动改写；UI 提供显式“转换为项目任务引用”的预览，只有验证成功后才可保存。
- 项目配置继续沿用现有脱敏、语法校验、内容哈希和生产环境确认机制；工作台不保存或向任务/工作流注入密码、token、私钥或完整环境变量。

### FR-040 统一运行中心

- 所有项目任务工作流运行必须创建持久 `RunRecord`，包含稳定运行 ID、项目/工作流或任务引用、触发方式、开始/结束时间、状态、步骤结果和安全脱敏摘要。
- 运行开始时保存不可变定义快照（任务引用解析结果、工作目录、步骤定义版本和完成规则），不得保存凭据、完整环境、原始敏感配置或无限制终端输出。
- 运行中心可按项目、状态、触发方式和时间筛选；显示待运行、运行中、等待确认、成功、失败、取消和“应用重启中断”。
- 运行中的任务可以沿用现有取消通道。应用重启后，未终态记录标记为“应用重启中断”，而不是错误地显示成功或继续执行。
- 每个设备最多保留最近 500 条记录；超过上限按最早已终态记录清理。清理不影响当前运行，且可由用户手动清空本地历史。
- 已存在的终端会话仍负责交互和实时输出；运行中心只保存长度受限、脱敏后的结构化摘要和会话引用。

### FR-050 入口与通知

- 工作流面板显示所关联的项目，并可跳转到对应工作台。
- 电子宠物在启用 Codex 联动时只展示一个最高优先级的活动项目运行摘要；点击进入运行中心。宠物不展示命令、路径、token 或输出内容。
- 任务完成、失败和等待确认使用现有桌面通知/状态语义，用户可关闭该类通知。

### FR-060 MCP 与审计

- 第一阶段 MCP 只增加项目能力、项目列表/详情、任务发现、任务引用预览、运行记录读取等工具；读取结果按本机项目范围过滤。
- MCP 的“保存为工作流”必须复用现有 preview → apply → revision 检查链路，不能直接写 YAML 或绕过 Rust 验证器。
- 不新增 MCP 执行、取消、Shell、SSH、RDP 或配置文件写入工具。此类能力进入后续安全评审，并要求每次操作有项目范围、动作 capability 和桌面端确认。
- 本地审计记录 MCP 工具名、项目 ID、时间、变更摘要、风险分类和结果码；不记录秘密、绝对路径、完整命令或终端输出。

## 非功能需求

- NFR-001：扫描、Git 元数据读取和任务解析必须在非 UI 线程执行；过期请求不得覆盖最新项目选择。
- NFR-002：所有持久化结构具有 schema version、向后兼容默认值、原子写入和可测迁移。
- NFR-003：运行记录写入失败不能改变已完成运行的真实状态；UI 显示“历史未保存”并保留可复制的即时摘要。
- NFR-004：新 provider、MCP 输入和项目引用均通过 Rust 后端重新验证；前端仅负责呈现。
- NFR-005：macOS、Windows 与 Linux 共享同一引用和运行记录 schema；平台不可用时给出明确状态。
- NFR-006：所有新增文档与源文件保持 UTF-8，并通过仓库 UTF-8 检查。

## 验收标准

1. 从现有项目任务历史启动后，用户能看到迁移后的项目档案；旧收藏、项目顺序和任务入口保持可用。
2. 项目概览能在 Git 可用和不可用两种情况下无阻塞加载，且不执行项目脚本。
3. Runme 与至少一个声明式任务 provider 的任务可同时被发现、按来源区分、预览且不执行。
4. 将任务保存为引用型工作流后，移动项目根目录会使运行前重新解析；未重新定位或引用失效时后端拒绝执行。
5. 已有 Shell 快照工作流能继续运行，且只有用户确认后才转换为项目任务引用。
6. 启动、失败、取消和应用重启中断的项目运行均出现在运行中心；记录不包含密码、token、私钥、绝对路径或未脱敏终端输出。
7. Codex 能发现和预览项目任务，但不能通过 MCP 直接运行任务或改写配置文件。
8. 相关 Rust/前端单元测试、`npm run build`、`cargo test`、`cargo check` 和 UTF-8 检查通过。

## 非目标

- 自动部署、GitHub webhook、构建镜像、域名、TLS、数据库、邮件、CDN 或云端运行时。
- 远程项目文件扫描、远程任务执行或多用户共享项目档案。
- 自动信任项目、自动执行扫描结果、自动安装任务工具或自动转换旧工作流。
- 保存完整终端历史、环境变量、凭据或可跨设备还原的绝对路径。
- 通用 Cron、离线补跑或绕过工作流现有调度与确认策略。
